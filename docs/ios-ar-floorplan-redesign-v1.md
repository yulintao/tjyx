# AR · 户型 · 分房 重构设计（v1）

范围：`refactor/no-compass` 分支持续重构。产品口径已收窄为「通过 AR/VR 分析，根据房屋布局合理安排家人居住」，本文只讨论这一条主线在三屏里的落位，不涉及设置页与其它栏目。

---

## 一、先把要解决的问题说清

现在的两个 Tab 是历史叠加出来的：

- **测绘（AR）**：AR 实景扫描、VR 手绘测绘、罗盘校准、形煞提示、现场存证拍照、3D 查看入口，全挤在一个页面里。用户在相机界面上要同时理解「我在测什么」和「这些按钮是干嘛的」。
- **布局（户型）**：顶部是户型图与房间编辑，中间是八宅体检清单（十几条吉凶条目平铺），底部塞了四个 3D/VR 入口按钮 + 导出分享。真正的核心动作——**给家人分房**——是第 498 行嵌进来的一个 section，等于埋在长滚动的中段。
- **引擎产出**：八宅、飞星、玄空、择日的结果都往结果页上摆。收窄之后这些不该是"卖点罗列"，只能作为**分房打分的依据**出现在需要它的地方。

一句话：**流程没有一个明确的"做完"状态**。测完了不知道下一步，看到户型了不知道能拿它干什么。

---

## 二、设计主张

把产品做成一条**三步流水线**，每一步只有一个主动作，做完自动把下一步推到眼前：

```
① 测绘  →  ② 布局  →  ③ 分房
（得到房间）  （房间落到户型）  （人落到房间）
```

- **测绘**解决"房子实际长什么样"，只有两种入口：实景扫描（LiDAR/相机）、手绘测绘（无 LiDAR 设备或无实景条件）。
- **布局**解决"房间在哪、边界对不对"，主画布是户型平面，允许拖拽房间框、标注朝向后保存。
- **分房**解决"谁住哪"，是唯一直接产出结论的动作，也是这个 App 存在的理由。

三步之间用**数据**串起来，不用用户记忆：`ShaSurveyStore` 里的当前住宅 → 布局页画布 → 分房面板读同一份房间数据。任何一步缺失，下一步显示空态并给出「先做上一步」的按钮，而不是灰着不解释。

---

## 三、屏级信息架构

### Tab 1 · 测绘

```
┌─────────────────────────────┐
│ 当前住宅                    │  顶部住宅条：缩略图 / 名称 / 房间数
├─────────────────────────────┤
│ [ 实景扫描 ]  主按钮，占满宽 │  LiDAR 可用 → 主入口
│                             │
│ [ 手绘测绘 ]  次按钮          │  无 LiDAR 或想改比例时用
├─────────────────────────────┤
│ 上次扫描：3 天前 · 8 间房     │  一行灰字，点进结果
└─────────────────────────────┘
```

扫描中不叠加无关按钮：只留「暂停/结束」「已识别 N 间」「光照不足」这类状态提示。扫描结束直接进**结果确认**：

- 房间列表（每行：房名 + 面积 + 是否连通）
- 点任一行 → 画布上高亮该房间，可改名、可合并、可删除
- 底部「保存到当前住宅」是唯一出口

原来的罗盘校准、形煞提示、现场存证拍照**移出主区**：校准归设置，形煞归分房结果的解释，存证归报告附件。它们不再是测绘 tab 的一等公民。

### Tab 2 · 布局

```
┌─────────────────────────────┐
│ 当前住宅 · 96㎡ · 3 间      │  住宅卡片
├─────────────────────────────┤
│                             │
│      户型平面画布            │  房间框 + 房间名 + 朝向标记
│      （可拖 / 可缩放）        │  选中房间高亮，显示面积与朝向
│                             │
├─────────────────────────────┤
│ [导入户型图] [编辑房间] [分房]│  底部三段操作条，等宽
└─────────────────────────────┘
```

- **画布是主角**，占屏 55% 以上；把此前 700pt 宽度上限的排版换成随宽度自适应的两栏（iPad / Duo 内屏：画布 60% + 右侧结果栏 40%；iPhone：单栏，结果栏下移）。
- **体检清单搬到右栏**，每条只留「标题 + 吉/平/凶」一行，点开才展开解释。这解决了现在十几条全平铺、把房间图挤出屏幕的问题。
- **四个 3D/VR 入口收成一个「3D 查看」按钮**，进二级页再选「当前户型 3D / 最近实景 / 最近仿真」——现在四个同权重按钮并排，用户根本分不清区别。

### 分房面板（核心）

从布局页操作条进入，独立 sheet，不嵌在滚动里：

```
┌─────────────────────────────┐
│ 家人分房            完成 ✕  │
├─────────────────────────────┤
│ 家人（拖到房间）             │
│  ● 父亲 1962 艮卦           │
│  ● 母亲 1965 兑卦           │
│  ● 女儿 2010 离卦           │
├─────────────────────────────┤
│ 房间                         │
│  □ 主卧 270cm×320cm 东南     │
│  □ 次卧 …                    │
│  □ 客厅 …                    │
├─────────────────────────────┤
│ [ 自动建议 ]  按命卦+方位打分 │
└─────────────────────────────┘
```

- 每个家人一行，拖到房间即落位；点「自动建议」按 `BaZhaiEngine` 的命卦—方位匹配度打分，给出一个初版分配，用户可逐个改。
- 落位后房间框上出现**三档色标**：吉＝金黄 `#FFC857`、平＝青绿 `#2FB5A8`、需注意＝粉 `#F97B93`（沿用现有警示粉）。这是唯一允许用颜色下结论的地方。
- 未填生辰的家人显示「补出生年」的轻按钮，点了就地补，不跳设置页。

### Tab 3 · 设置

不动。只保留身份档案入口（家人列表在这里维护），其余保持现状。

## 五、保留与退场的清单

**继续服务主线**（不删）：
- `ShaSurveyStore` — 当前住宅与房间数据，三屏共用
- `BaZhaiEngine` — 命卦与八宅方位，分房打分的唯一依据
- `XuanKongDeepAnalyzer` / `PurpleWhiteEngine` — 房间气口与方位的辅助解释，只在条目展开时出现
- `FloorplanEngine` — 户型房间几何与朝向

**退出一等公民**：
- 飞星、择日：降级为报告附录，不在主界面出现
- 罗盘校准、形煞提示、存证拍照：移入设置 / 报告附件
- 长卷导出：已下线，不再复活

## 六、实施顺序（按提交粒度切）

| 阶段 | 内容 | 可独立验证 |
|---|---|---|
| P0 | 布局页拆三区（住宅卡片 / 画布 / 操作条），体检清单移到右栏，四个 3D 入口合一 | 打开布局页即可看 |
| P1 | 分房面板独立 sheet + 自动建议 + 三档色标 | 需有人与房间数据 |
| P2 | 测绘页三段式（引导卡 / 扫描态 / 结果确认） | 需真机相机 |
| P3 | 报告页（把形煞、气口、分房结论汇总成一页）——**暂缓** | 纯渲染 |

P0、P1 不依赖真机相机，可以先做；P2 必须真机验证；P3 最后做，因为它依赖前三步的数据形状。

P3 暂缓的两个理由：一是形态没定——早期长卷导出已下线且不复活，报告页是「屏内一页摘要」
还是「摘要 + 单页图片分享」需要先验证前两步的数据形状；二是这一批 Swift 改动还没有过一次编译，
先把编译与真机验证走通，再决定报告页要不要做。

**文案政策**：新增界面文案时八语一起补（zh-CN / zh-TW / en / ja / ko / th / vi / id），
译文由实现方起草、交用户审。此前因缺文案而搁置的 P0「当前住宅卡片」按此政策解禁。

---

## 七、明确不做

- 不再新增 Tab；三 Tab 结构不动。
- 不在主界面出现任何购买、额度、会员字样（收费暂停期间）。
- 不把引擎结果做成"每日推送"或"运势"类内容——那是已删掉的方向。
- 不为单个页面引入新的设计系统；所有颜色走上面的 token，改色只改 `AppPalette.swift`。
