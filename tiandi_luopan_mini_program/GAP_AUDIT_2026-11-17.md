## 六、关于「翻译」：多语种现状

若这里指的是**语言文案**而非功能移植：

- iOS：`LocalizationManager.swift` 6947 行、**6616 条 key-value**，覆盖 8 语种（zh-Hans / zh-Hant / en / ja / ko / vi / th / id），全量约 721 KB。
- 小程序：**没有任何 i18n 框架**，2527 条中文文案硬编码在 JS/WXML 里（约 1.7 万汉字），`settings` 语言项固定「简体中文（固定）」。
- 结论：除简体中文外，其余 7 语种**一条也没翻译**。要支持，等于新建 key 表 + 回填 2500 条文案，工作量和重写一遍 UI 文案相当。当前产品决策是「仅简体中文」，所以这项按不做处理，但需要明确记录：**不是遗漏，是主动不做**。

### 13.5 `wx://not-found` 报错修复（同日，两处原因）

现象：控制台 `Component is not found in path "wx://not-found"`，页面渲染中断。

**原因一（真实主因）：14 个页面缺 `index.json`。**
项目开启了 `lazyCodeLoading: "requiredComponents"`（`app.json` 与 `project.config.json` 各一处）。在此模式下，页面没有自己的配置文件时，框架会拿不到该页的组件声明表，解析时落到 `wx://not-found`，控制台常同时出现 `Page "pages/xxx/index" has not been registered yet`。缺配置的 14 页：`analysis / ar / bazhai / fenjin / floorplan / gua64 / qimen / sanhe / settings / sha / tianji / xuankong / zeri / zibai`。

修复：为这 14 页补 `index.json`（`{"usingComponents": {}}`），现 27 页全部具备页面配置；同时移除 `pages/index/index.json` 里已无必要的 `componentPlaceholder`（校准组件体量很小，无需占位注入）。

**原因二：`pages/sanhe/index.wxml:54` 用了 HTML 的 `<br/>`。**
小程序没有 `<br>`，WXML 会把未知标签当**自定义组件**解析，未声明即退化为 `wx://not-found`。已拆成两个 `<view class="footnote">`（`宜来水` / `宜去水` 各一行）。

**防复发**：`scripts/check-components.js` 现做四件事——① 每页必须存在 `index.json`；② wxml 标签与内置组件表、`usingComponents` 比对，未声明即报错；③ 声明的组件目标 `.js/.wxml` 必须存在；④ 标签栈开闭配平（跳过注释、属性引号与自闭合）。全项目复核：未发现未声明/缺失组件，标签全部配平，27 页 JSON 全部可解析。
